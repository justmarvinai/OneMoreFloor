### Part 4 — decisions taken after release, in the polish rounds

These change what the brief says. They are recorded here rather than folded silently into the code, because §0.3 makes the brief the source of truth and a contradiction the owner *chose* is still a contradiction someone will find in six months and wonder about.

Q28–Q35 were settled in the fifth polish round; Q36–Q45 in the sixth. Nothing in either round loosened the two rules the rest of the game leans on: **every item source still emits inside the character's Power-Level bracket** (§13), and **death still destroys nothing owned** (§3.3). Where a new feature could have bent one, the entry below says how it was stopped and which test holds it.

| **Q30** | Backpack size as a third account upgrade | **Owner's instruction, fifth polish round: add it.** §15 says "exactly two account upgrades exist in EA 0.1. Do not add more"; the backpack makes three. It is bought with gold from the playing character's purse like the other two, belongs to the account and survives a reset (Q4), and runs 20 → 50 sockets in steps of five. What §15 was protecting is protected the same way it always was: the upgrade kind stays a closed union in `domain/account/upgrades.ts`, so a fourth cannot appear without an edit there and a line here. | `content/balance/account.ts`; `domain/account/upgrades.ts`; SAVE_SCHEMA v6 |

No brief line is contradicted; §3.6 never specified a rate. | BALANCE.md §7 |
| **Q32** | Auto-climb | **Owner's instruction, fifth polish round: add it, deliberately slow, and a background mode at hero level 500.** §3.1's "one more floor" press stays the default and the manual path is untouched; auto-climb is an opt-in that presses it for you. | BALANCE.md; `domain/tower/autoClimb.ts` |
| **Q33** | Where the fifth round's new features live | **Owner's instruction, fifth polish round: add a best-floor ghost, loadout presets, a bestiary, run history, milestone rewards, reforge, salvage, a pity-free gacha wish list, and player-side enemy affixes at level 100.** Each is placed where its question is already asked rather than on a screen of its own: the ghost and milestones on the tower trail, run history and the bestiary on one new Records destination, presets on the Character sheet, salvage and reforge in the gear dialog beside sell and ascend, and the wish list under the rates it must not contradict. | `docs/UI_FANTASYUI_MAP.md` §2, §8 |
| **Q34** | Whether a wish list touches the printed odds | **No, and it is built so it cannot.** The wish steers *which slot* a gear prize fills and nothing else — not its rarity, not its budget, not whether a pull pays gear. Every number on the rates card is about rarity, so a wish moves none of them, and §16.2's "no overshooting" still runs through the one generator. Pity-free by construction: there is no counter to keep. | `domain/gacha/gacha.ts` |
| **Q35** | Player-chosen enemy affixes ("curses") | **Owner's instruction, fifth polish round: add an enemy affix system on the player's side, unlocked at level 100.** Six curses, three at once. Each raises stats on every enemy — never trades, unlike the procedural modifiers — and multiplies what every floor pays in gold, experience and materials. Two things it must never touch, and the tests say so: the **bracket** a drop comes from, so §13 holds with a full set on; and the **seed**, so a cursed floor is the same fight with harder numbers and a run stays replayable. | `content/enemies/curses.ts`; `domain/tower/curses.ts`; BALANCE.md |
| **Q36** | Echoes of the Spire | **Owner's instruction, sixth polish round: a permanent progression layer.** An account currency paid **once per floor the account has never cleared** — re-climbing earns none, so it cannot be farmed, and death takes none away, so the second hero starts ahead of where the first did. Six nodes, five ranks each, no prerequisites. Two carry rules the rest of the build depends on: Patience is clamped below half whatever is bought, so Q32's auto-climb never becomes the fastest way to play; and Coffers adds backpack sockets *above* Q30's purchased ceiling rather than inside it, so a climb-earned reward does not stop mattering the moment the shop is affordable. Nothing echoes buy touches the bracket. | `content/balance/echoes.ts`; `domain/account/echoes.ts`; SAVE_SCHEMA v7 |
| **Q37** | Expeditions | **Owner's instruction, sixth polish round: timed missions that run while you are away.** Priced in the only unit the game has: an hour away is worth a handful of *floors* at a fraction of the hero's record, so a player who is climbing always beats one who is waiting. Two things a route never pays — **gear**, because every item comes from a source §13 brackets and a timer is not allowed to be a fourth one, and **echoes**, which are paid for new ground alone (Q36). Materials come from the *claiming* hero's bracket. A recall pays nothing, deliberately: a partial payout would make "send, recall, send again" the best way to run the board. Dispatch capacity is one party per character slot the account has opened, which gives §15's slot upgrade a reason to exist for a player with no interest in a second hero. The pitch said "idle heroes"; requiring a second hero would have left the feature invisible for hours behind a purchase, so the roster sets *capacity* instead. | `content/expeditions/`; `domain/expeditions/expeditions.ts` |
| **Q38** | Class talents | **Owner's instruction, sixth polish round: a talent tree per class, a point per level, a gold-priced respec.** Eleven talents in four rows, five ranks each; deeper rows cost more per rank and open on points already committed rather than on prerequisites between nodes — a tree that gates C behind B is a longer way of saying "buy B". Two constraints bind it to the brief: **nothing here can raise Speed** (the effect type is built on the stat union that excludes it, so §6 holds by construction rather than by comment), and **every point is visible to the bracket** — stat talents through the hero's stat total, the rest counted explicitly, so §13 cannot be dodged by a build whose value is rules rather than numbers. Respec is priced at the rate floors pay gold, so changing your mind is about two floors of climbing at every point on the curve. | `content/balance/talents.ts`; `content/talents/`; `domain/talents/talents.ts` |
| **Q39** | The Boss Rush | **Owner's instruction, sixth polish round: the ten gates back to back, with a personal best.** One health bar, no refill between gates, and the ten authored bosses fought at `record x i / 10` — which is exactly the tower's own ladder at a record of a hundred and spreads across whatever depth the hero has earned past it. It **pays for new ground only**, the same rule the echoes run on, so a rush cannot be farmed; and it **costs nothing to lose** — the run, the record and the seed are untouched, because a side mode that could undo an hour of climbing is one nobody with an hour of climbing behind them would open. It emits no quest events but the gold it paid: a rush that ticked "clear 12 floors" would let a player finish a climbing quest without climbing. | `content/balance/bossRush.ts`; `domain/bossRush/bossRush.ts` |
| **Q40** | Deeds | **Owner's instruction, sixth polish round: an achievement ledger.** Nine deeds, three tiers each, on the Records screen. **Every deed counts something the game was already counting** — seven read the quest board's own event stream and two are high-water marks read off the account — so nothing here has a counter that can drift out of step with what it measures. The ledger hangs off `withQuests`, the single place every event passes through, rather than being recorded at twenty call sites. What a tier pays is priced against the depth the account has reached, never fixed at authoring time; materials come from the claiming hero's bracket and it never pays gear (§13). First tiers are deliberately shallow, because a ledger whose first payout is hours away teaches a new player it is not for them. | `content/deeds/`; `domain/account/deeds.ts` |
| **Q41** | Branching paths | **Owner's instruction, sixth polish round: a route choice per stretch of the climb.** A fork every ten floors — the tower's own gate cadence, so it lands where a player already stops to look up. The task said "per band"; the content bands are six and the last runs from floor 101 upward, so a fork per band would be a feature that dies at floor 101. Six roads, three offered, and one of the three is always the plain way: a fork whose every branch is a gamble is not a choice, it is a tax. What is offered comes from the run seed, so a road not taken was really there. Inherited whole from Q35: a road never touches the **bracket** and never touches the **seed**. The choice belongs to the run and dies with it; the fight controls stay shut until one is taken, and auto-climb stops at a fork rather than deciding for the player. | `content/paths/`; `domain/tower/paths.ts` |
| **Q42** | Companions | **Owner's instruction, sixth polish round: a pet that joins the fight.** A real third combatant — its own health bar, its own turn between the hero's and the enemy's, its own card, and it can be struck down without the fight ending. Its stats are read off the hero's, which settles gear (it needs none), §13 (it has no bracket of its own) and obsolescence (it cannot happen) in one stroke. Each species draws a different share of the enemy's attention and gives a different aura, so the choice is a bargain rather than a ranking. The roster and its levels belong to the **account** so death costs none of it (§3.3); which one is out belongs to the character. Speed appears in a companion's own ratios and never on the hero — the aura type cannot express it (§6). What a companion is worth counts towards Power Level, for the same reason uniques and talents do. | `content/pets/`; `domain/pets/pets.ts` |
| **Q43** | The Workbench | **Owner's instruction, sixth polish round: somewhere to turn what a climb leaves behind into what it needs.** At the Alchemist's counter: transmute materials up the tier ladder at a fixed rate, and brew a draught from materials instead of gold. Both are conversions between things the player already has, so neither is a new source and §13 has nothing to police. | `domain/items/workbench.ts`; `ui/screens/merchant.ts` |
| **Q44** | Elites | **Owner's instruction, sixth polish round: champions on ordinary floors.** From floor 5, a floor may raise a champion: the same enemy, larger, always carrying a modifier, and always paying gear. Never on a boss floor — a gate is already the thing an elite is a small version of, and stacking them would make one floor in eleven impassable. Rolled from the floor's own seed stream so the preview, the trail mark and the fight agree without anything being stored. | `content/balance/enemies.ts`; `domain/tower/floors.ts` |
| **Q45** | Item sets and named uniques | **Owner's instruction, sixth polish round: sets with thresholds, and named pieces that carry rules.** Set membership is a property of the **base**, not a mark rolled onto an instance, so no save shape changed and a set never goes obsolete in an endless tower. Uniques **gate on rarity rather than promote it** — the rule is one filter over bases in `pickBase`, so drops, shelves and rites cannot disagree, and the printed rate table stays true to the decimal. A unique's power is a rule rather than a stat, so it is counted into Power Level explicitly: §13's bracket cannot be dodged by a piece whose whole value is invisible to it. | `content/items/sets.ts`; `content/items/uniques.ts`; `domain/items/sets.ts` |
